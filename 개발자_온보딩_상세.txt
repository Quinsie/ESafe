KESCO 전기재해위험지수 관리시스템 개발자 온보딩 상세
작성일: 2026-03-12

1. 시스템 한 줄 요약
- Python으로 위험 분석 결과를 만들고, Oracle/H2에 적재한 뒤, Spring MVC + MyBatis + JSP로 조회하는 하이브리드 구조다.

2. 기술 스택
- 분석/전처리
  - Python
  - pandas, geopandas, shapely 계열
- 웹/API
  - Java 8 타깃
  - Spring MVC
  - MyBatis
  - JSP + jQuery
- 실행 환경
  - Tomcat 8.5.x
  - JDK 11
  - Maven 3.9.x
  - H2 / Oracle
- 지도
  - VWorld 2D 타일 + OpenLayers
  - VWorld 3D

3. 핵심 디렉터리
- `api`
  - 웹 애플리케이션 본체
- `db`
  - Oracle 스키마/뷰/적재용 SQL 및 배치 스크립트
- `설비데이터`
  - 일반용/자가용 설비 CSV
- `사업소별 분석결과`
  - 본부/사업소 단위 최종 분석 결과 CSV/SHP
- `기상특보`
  - 기상 경보 수집/가공 스크립트와 CSV

4. 처음 봐야 할 코드
- `api\src\main\java\egovframework\com\risk\web\RiskCombinedController.java`
  - 목록/상세/요약/지도 API 진입점
- `api\src\main\resources\egovframework\sqlmap\risk\RiskCombined_SQL.xml`
  - 실제 조회 SQL과 지도용 쿼리
- `api\src\main\java\egovframework\com\risk\service\impl\RiskCombinedServiceImpl.java`
  - 설비 상세 복원 등 서비스 로직
- `api\src\main\webapp\resources\js\risk-nationwide-risk-map.js`
  - 전국 위험지도 프론트 로직
- `api\src\main\java\egovframework\com\risk\util\RiskMapPolygonResolver.java`
  - 사업소 분석 SHP에서 건물 폴리곤을 읽어 지도 응답에 붙이는 유틸

5. 오늘 기준 반드시 알아야 할 변경점
- H2 데이터 범위가 소규모 샘플이 아니라 `광주전남본부직할` 전체 건물 217,241건 기준으로 확장되어 있다.
- 설비 이력도 전량 적재 상태다.
  - 총 2,064,816건
- 지도의 등급 기준은 이제 `종합점수(COMBINED_SCORE)` 기준이다.
  - 건물 상세의 `종합`과 맞춰야 한다.
- 지도는 줌 단계에 따라 구역/건물 포인트/건물 폴리곤을 나눠 조회한다.
- 지도 체크박스 필터는 `riskCdList=A~E`를 서버로 넘겨 현재 선택 등급만 조회한다.

6. 전국 위험지도 구조
- JSP

  - `selectRiskMapBuildingLayer.do`
  - `selectRiskMapBuildingPolygonLayer.do`

  - 줌 16 이상: 건물 폴리곤
- 현재 상한
  - 건물 포인트 20,000
  - 건물 폴리곤 1,500

  - 설비 상세 조회 시 원본 CSV에서 찾아 동적으로 복원한다.

11. 자주 생기는 실수
- H2에서만 되는 코드를 Oracle까지 자동으로 된다고 가정하는 것
- 지도 등급 기준을 `TOTAL_SCORE`로 착각하는 것
- 설비 이력 적재 수가 원본 행 수보다 큰 이유를 주소 중복 건물 매핑 때문이라는 점을 놓치는 것
- 캐시 때문에 이전 JS를 보고 있는데 서버 문제로 오인하는 것

12. 권장 작업 순서
1. H2로 서버 기동
2. `riskDashboard.do`, `riskBuildingList.do`, `riskNationwideRiskMap.do` 확인
3. `RiskCombinedController`와 `RiskCombined_SQL.xml` 읽기
4. 설비 적재 스크립트와 원본 CSV 구조 확인
5. Oracle 반영이 필요하면 `db` SQL과 실행 스크립트까지 같이 본다.
